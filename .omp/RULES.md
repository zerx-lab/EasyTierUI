# EasyTierUI hard rules

AGENTS.md is the authority (subagents receive it through CLAUDE.md); these are the rules every agent keeps in view.

- Rust has no panic paths outside tests: no `unwrap`/`expect`/`panic!`/`unreachable!`/`assert!` family/`todo!`/`unimplemented!`/`dbg!`, no unchecked indexing, no `str` byte slicing, no unchecked arithmetic on counters and offsets. Use `?`, `let … else`, `.get()`, `checked_*`/`saturating_*`, typed `thiserror` errors; degrade at event / row / poll boundaries and show recoverable errors in the UI. Read `rule://rust-error-handling` before writing fallible Rust.
- No `unsafe` anywhere (`unsafe_code = "forbid"`); never loosen `Cargo.toml` `[lints]` or `clippy.toml`.
- One client, every platform, every feature: roles (node, console, control-plane host) and targets are switched in the same UI everywhere; a feature the platform cannot run locally acts on a remote target and says so. EasyTier is decoupled and freely upgradable: desktops run the official `easytier-core` / `easytier-web` binaries as separate processes; only `src/core/embedded/` (mobile) may link EasyTier's crates, after the user approves; nothing outside `src/core/` and `src/deploy/` names EasyTier types. `rule://easytier-core-boundary`.
- Secrets never reach logs, argv, derived `Debug`, fixtures or commits (environment only for an easytier-web secret its version reads from its own variable); the RPC portal binds `127.0.0.1:<port>` with a loopback whitelist; a hosted or deployed easytier-web replaces the seeded `admin`/`admin` and `user`/`user` passwords before its API leaves loopback, keeps registration and auto-created accounts off; downloads are sha256-verified, images pinned by digest; imports are shown before they apply. `rule://easytier-config-security`.
- UI follows DESIGN.md: colors from `theme.json` tokens via `theme()`, the spacing / type / radius scale, both appearances, every state, zh-CN and en strings. `rule://ui-design-system`.
- No `sudo`, system services, route / interface / firewall changes, a real TUN, or applying deployment artifacts to a real server from an agent; test the core with `--no-tun` on loopback and easytier-web on loopback with a temporary `--db`.
- Subagents never run `cargo build`/`test`/`clippy`/`run` or `nsh run`/`test`/`package`/`build` (at most `cargo check`); the main session runs checks one at a time. Done means checked: `/verify`, and report what ran.
